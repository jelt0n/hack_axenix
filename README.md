# Java Blueprints

Веб-среда для исследования Java-программ через код и граф выбранного метода.

Первый этап ([issue #2](https://github.com/jelt0n/hack_axenix/issues/2)): импорт `.java`, список методов и конструкторов, граф последовательностей и `if/else`, переход от блока к строке кода, экспорт Java с сохранением комментариев и оформления, восстановление временного проекта после обновления страницы.

Второй этап ([issue #3](https://github.com/jelt0n/hack_axenix/issues/3)): сценарии stdin, общая очередь и сравнение исходной и рабочей версий через настоящий Java-компилятор в ограниченных Docker-контейнерах. Совпадение относится только к указанным входам.

Третий этап ([issue #4](https://github.com/jelt0n/hack_axenix/issues/4)): редактирование рабочей Java в Monaco, сохранение ревизий и явное обновление графа с сохранением последней корректной модели при синтаксической ошибке.

Четвёртый этап ([issue #5](https://github.com/jelt0n/hack_axenix/issues/5)): структурные действия над операциями графа и атомарное обновление Java и модели.

Пятый этап ([issue #6](https://github.com/jelt0n/hack_axenix/issues/6)): циклы, switch и переходы управления. Проверенные варианты и открытые пункты описаны в [матрице управления Java](docs/java-control-flow.md).

Шестой этап ([issue #7](https://github.com/jelt0n/hack_axenix/issues/7)): try/catch/finally, классы, исключения, консоль и коллекции проверены через полный путь структурной правки и исполнения. Конкретные API и ограничения перечислены в [матрице Java](docs/java-coverage.md).

## Требования

- Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Node.js 22.12+ или 24 LTS, npm.
- JDK 17+ с модулем `jdk.compiler`; рекомендуем JDK 21+. Команда `java` должна быть в `PATH`.
- Linux для совместного запуска через скрипт разработки.

## Подготовка и запуск

```bash
python3 scripts/setup.py
python3 scripts/dev.py
```

Откройте **http://127.0.0.1:5173**. API и его интерактивное описание доступны на **http://127.0.0.1:8000/docs**.

Подготовка устанавливает зависимости по `uv.lock` и `package-lock.json`, загружает фиксированные JavaParser/Gson из Maven Central и тестовый Chromium. Контрольные суммы Java-зависимостей находятся в `java/dependencies.json`. После подготовки приложение работает без внешних API, шрифтов и модели ИИ.

Нажмите **«Открыть пример»** либо загрузите свой `.java` до 256 КБ. Выберите метод слева; нажатие на блок выделяет соответствующие строки. Кнопка **«Экспорт Java»** скачивает код, напечатанный JavaParser из AST. Исходная версия хранится отдельно.

Для отдельных процессов:

```bash
# Терминал 1
.venv/bin/uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000

# Терминал 2
npm run dev
```

Для проверки поведения нужен Docker на Linux. Соберите доверенный образ и запустите отдельный исполнитель в третьем терминале:

```bash
docker build -t java-blueprints-runner:dev runner
.venv/bin/python -m backend.worker
```

API и исполнитель должны использовать один `BLUEPRINTS_DATA_DIR` (по умолчанию `.data`). Исполнитель получает доступ к Docker, API — нет. Кнопка **«Проверить поведение»** открывает 1–5 сценариев с именем и stdin; класс с `main` определяется автоматически либо задаётся полным именем. Без исполнителя задание остаётся в очереди. Результат показывает stdout, stderr, код завершения и ошибку каждой версии; изменение входов помечает предыдущий результат устаревшим.

## Редактирование Java

Внизу окна кода нажмите **«Редактировать Java»**. Monaco загружается отдельным модулем вместе с локальным worker; CDN и внешний языковой сервер не нужны. Кнопка **«Просмотр кода»** возвращает режим исследования, вкладка **«Исходный»** показывает неизменяемую исходную версию.

Правки сразу сохраняются как черновик текущей вкладки браузера и переживают обновление страницы. Нажмите **«Обновить граф»**, чтобы сохранить рабочий текст на сервере новой ревизией и разобрать его JavaParser. До этого черновик хранится в этой вкладке; экспорт в интерфейсе включает и несохранённый текст.

При синтаксической ошибке рабочий текст остаётся сохранённым, выводятся строка и столбец ошибки. Последний корректный граф остаётся виден с отметкой «устарел»; переходы по его старым диапазонам отключены. После исправления снова нажмите **«Обновить граф»**. Выбранный метод сохраняется по классу и сигнатуре, если они остались в программе.

Проверка поведения относится к сохранённой ревизии: пока есть черновик, запуск отключён, предыдущий результат отмечен устаревшим. При конфликте с другой вкладкой текст сохраняется отдельно, а интерфейс предлагает загрузить серверную версию или явно сохранить свой текст поверх неё.

## Правки графа

Выберите операцию или условие в графе, измените «Код блока» и нажмите
«Применить правку». Для условия вводится одно Java-выражение, для операции — один
оператор с точкой с запятой. «Добавить операцию» позволяет выбрать тело метода,
вложенную последовательность, тело цикла или ветку `if/else`/`switch` и позицию вставки, включая пустую
ветку. Для веток без фигурных скобок приложение добавит необходимый блок.
Кнопки «Переместить выше/ниже» меняют порядок в текущей последовательности;
«Удалить операцию» удаляет выбранную операцию. Связи строятся приложением.

Подтверждённое действие сохраняет Java, граф и ревизию вместе. Исходная версия и
нетронутые методы сохраняются. Результат прежней проверки становится историческим;
кнопка «Проверить» выполняет сравнение для новой ревизии. При несохранённом тексте,
устаревшем графе или конфликте вкладок структурные действия отключены. Черновик,
введённый во время запроса, сохраняется отдельно до явного разрешения конфликта.

Структуры управления не заменяются целиком через поле операции. Условия циклов и
селектор switch редактируются выражением; заголовки и синтетические шаги циклов —
текстовым редактором. Внутренности непрозрачных блоков и перенос между областями
видимости пока не поддерживаются. Синтаксис проверяет JavaParser; ошибки типов,
ссылок на переменные и другие ошибки компиляции показывает настоящая проверка
поведения. Структурно недопустимые действия отклоняются без изменения проекта.

## Диагностика и оценка сложности

После сохранения Java и обновления графа нажмите «Анализировать». Анализ не изменяет код,
не исполняет программу и не требует ИИ или сетевого доступа. Находка содержит объяснение,
рекомендацию и переход к методу, диапазону исходника и соответствующему блоку графа.
Находки о вложенности циклов ведут к условию цикла; внутри непрозрачной конструкции
выделяется содержащий блок, а диапазон кода остаётся точным.
Результат привязан к ревизии: после правки он устаревает, а переходы отключаются.

Правила первого набора:

- `long-method`: больше 40 физических строк от начала объявления до конца метода/конструктора,
  включая пустые строки и комментарии; ровно 40 строк не вызывает находку.
- `deep-nesting`: первая управляющая конструкция на третьем уровне вложенности на каждом пути;
  учитываются if/else, циклы, switch, try и synchronized, обычные блоки не увеличивают уровень.
  Подсчёт не переходит в отложенный код лямбд или вложенные классы.
- `constant-condition`: буквальное `true` или `false` в условии if, в том числе в скобках.
  Вычисляемые условия вроде `1 == 1` не сворачиваются.
- `nested-loops`: каждый цикл внутри другого цикла. Это указание проверить повторную работу,
  а не доказательство квадратичной сложности или наличия дефекта.

Big O — консервативная верхняя оценка для методов с примитивными параметрами/локальными
переменными и массивами примитивов: последовательности, if и счётные `for (int i=0; i<bound; i++)`.
Граница — неизменяемый параметр `int`, длина массива-параметра или неотрицательная константа int.
Изменение счётчика вне шага цикла и зависимые границы отвергаются. Стоимость примитивных
операций и индексирования считается O(1), размеры — неотрицательными; ошибки выполнения и
переполнение не моделируются. Независимые размеры сохраняются в формуле: например,
`O(n + n · m)`; фиксированные границы дают O(1). Допущения показаны у каждой известной оценки.

Конструкторы (из-за неявного super() и инициализаторов), вызовы методов (включая библиотечные
и рекурсию), создание объектов, объектные параметры,
лямбды и неподдержанные конструкции дают «не определена» с причиной. Это намеренно узкий
набор; наличие AST само по себе не подтверждает знание стоимости операций. Оценка не обещает
ускорения и не доказывает сохранения поведения. Отсутствие находок не гарантирует отсутствие дефектов.

## Проверки

```bash
.venv/bin/pytest
.venv/bin/ruff check backend tests scripts
.venv/bin/ruff format --check backend tests scripts
npm run typecheck
npm run build
npm run test:e2e
# Настоящий Docker, без подмены компилятора и исполнения:
python3 scripts/test_runner.py
python3 scripts/test_runner.py --browser
```

API-тесты работают с настоящим JavaParser и временным SQLite-хранилищем. Браузерный тест запускает API и Vite, загружает реальный файл, переключает методы, проверяет выделение строки, восстановление проекта и содержимое скачанного файла.

Docker-тесты проверяют кириллицу, исключения, различия вывода, ошибку компиляции, бесконечный цикл, переполнение вывода и памяти, ограничения контейнера, очередь и очистку. Без Docker эти тесты явно пропускаются. Браузерные проверки используют отдельные порты 15173/18000 и временную базу, не затрагивая ручное демо. `scripts/test_runner.py --remote` поддерживает локальный Unix-сокет `.cache/ssh/docker.sock` и Docker CLI `.cache/bin/docker`, подготовленные оператором; учётные данные не входят в репозиторий.

На машине с ограничениями песочницы серверы, браузер и TestClient должны иметь разрешение на локальные сокеты и потоки. Для собственного запуска достаточно обычного пользовательского процесса.

## Архитектура

- `frontend/`: React, TypeScript, React Flow. Отображение методов, исходника и графа.
- `backend/`: FastAPI, проекты и очередь в SQLite, отдельный исполнитель Docker.
- `java/src/`: JavaParser разбирает исходник как данные, строит граф и использует `LexicalPreservingPrinter` для генерации Java.
- `runner/`: JDK 21 с Java SE и launcher в отдельном закрытом Java-модуле для выполнения пользовательской Java.
- `tests/`: проверки публичного API и браузерный сценарий.

Java-модуль разбора компилируется при первом импорте и повторно после изменения его исходника. JVM для разбора ограничена 128 МБ heap; одновременно выполняется один разбор. Импорт и экспорт не запускают загруженную программу. Исполнение происходит только по запросу проверки поведения в отдельном контейнере.

## HTTP API

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/api/projects` | Импорт JSON с `filename` и `source`, проект и cookie сессии |
| GET | `/api/projects/current` | Последний проект текущего посетителя |
| GET | `/api/projects/{project_id}` | Метаданные, методы, исходная и сгенерированная версии |
| GET | `/api/projects/{project_id}/methods/{method_id}/graph` | Узлы, связи, диапазоны исходника и пояснения |
| GET | `/api/projects/{project_id}/export` | Скачивание сгенерированного Java |
| GET | `/api/health` | Готовность HTTP API |
| POST | `/api/projects/{project_id}/source` | Сохранение `source` с ожидаемой `revision`; конфликт — HTTP 409 |
| POST | `/api/projects/{project_id}/rebuild` | Разбор сохранённой `revision`, диагностика и обновление корректной модели |
| POST | `/api/projects/{project_id}/graph-edits` | Атомарная правка блока или последовательности с ожидаемой `revision` |
| GET | `/api/runner` | Доступность исполнителя |
| POST | `/api/projects/{project_id}/checks` | Снимок ревизии и сценариев в очередь, HTTP 202 |
| GET | `/api/checks/{check_id}` | Состояние, позиция и результат своей проверки |
| POST | `/api/projects/{project_id}/analysis` | Анализ актуальной ревизии `{revision}`: находки, диапазоны, блоки и Big O; устаревшая модель — 409 |
| GET | `/api/projects/{project_id}/checks/latest` | Последняя проверка проекта для восстановления страницы |

Чужая или отсутствующая сессия получает `404` для проекта, графа и экспорта. Cookie сессии — HttpOnly, SameSite=Strict; при HTTPS также Secure. Содержимое исходника не вставляется как HTML.

## Данные и ограничения

- Временные проекты сохраняются в `.data/projects.sqlite3`, срок доступа — 24 часа. Переменная `BLUEPRINTS_DATA_DIR` задаёт другой каталог. Истёкшие проекты удаляются при следующем импорте.
- Рабочий код редактируется в Monaco и через операции графа, включая тела циклов и поддержанные ветки switch.
- Поддержаны `while`, `for`, `do/while`, `foreach`, switch с двоеточиями и стрелочными блоками, непомеченные `break`/`continue`, `return` и `try/catch/finally`. Исключения показаны возможными путями; finally учитывает ожидающий переход. `try-with-resources`, switch-выражения, шаблоны/guards, метки и другие неподдержанные формы показываются целиком с пояснением и сохраняются. Это не заявляется полным покрытием обязательной базы; см. [управление](docs/java-control-flow.md) и [базу Java](docs/java-coverage.md).
- Объявления методов без тела сохраняются и показываются в списке; для них нет графа выполнения.
- Анализ качества кода и преобразования ещё не реализованы. Проверка поведения сравнивает исходную версию с сохранённой рабочей, включая пользовательские текстовые правки.
- Версию JDK и полную матрицу Java scope нужно сверить с отдельным техническим документом организаторов, когда он появится.

## Сборка интерфейса

```bash
npm run build
.venv/bin/uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000
```

После сборки FastAPI также обслуживает интерфейс на порту 8000. Публичное развёртывание и измерение ресурсов сервера входят в отдельную задачу #11.

## Контейнерный запуск

```bash
npm run build
docker build -t java-blueprints-runner:dev runner
export DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)
docker compose up -d --build
```

Интерфейс доступен на **http://127.0.0.1:8000** хоста. Compose публикует порт только на loopback; публичный доступ и HTTPS настраиваются отдельно. Том `projects` хранит временные проекты и очередь. Docker socket подключён только к доверенному исполнителю; его доступ к Docker даёт полномочия управления хостом, поэтому этот сервис не имеет публичного API.

Очередь допускает одно активное задание, до 20 незавершённых заданий всего и до двух на сессию. Версии запускаются последовательно в свежих контейнерах: UID 1000, сеть отключена, read-only root, без capabilities, 1 CPU, 512 МБ RAM без swap, 64 процесса, 64 МБ `/work` и 16 МБ `/tmp`. Компиляция ограничена 25 секундами, выполнение — 5 секундами, суммарный stdout/stderr — 64 КБ; stdin одного сценария — 32 КБ UTF-8. После выполнения и ошибки контейнер удаляется; при восстановлении исполнитель удаляет контейнеры своего deployment и помечает прерванное задание незавершённым.

Обычный stderr сравнивается побайтно без нормализации. Для необработанного исключения launcher передаёт тип, сообщение и цепочку причин; его стек передаётся и показывается отдельно от обычного stderr, поэтому номера строк стека не влияют на сравнение. Отчёт JVM подписывается одноразовым ключом, переданным вне пользовательского stdin. Ошибки компиляции, таймауты, превышение лимитов и недостоверный отчёт дают незавершённую проверку, а не совпадение.
