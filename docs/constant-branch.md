# Упрощение константной ветки

Выберите в графе условие `if` с буквальным `true` или `false`, в том числе в скобках.
Откройте «Предпросмотр упрощения»: показаны исходный фрагмент и результат. «Отмена»
не меняет проект. «Применить и проверить» сохраняет преобразование и запускает
обычную проверку поведения на текущих сценариях и классе с main из панели проверки.

## Поддержанные случаи

- При `true` остаётся then, при `false` — else; false без else заменяется пустым блоком.
- Выбранная ветка остаётся отдельным блоком `{ ... }`, включая исходные фигурные скобки.
  Объявленные в ней переменные не выходят в окружающую последовательность.
- Поддержаны ветки без фигурных скобок, вложенные условия, пустые ветки и простые
  операции. За один запрос упрощается только выбранный if.
- Комментарии и форматирование за пределами заменяемого if, другие методы и исходная
  версия сохраняются. Патч проверяет точное совпадение диапазона и токенов исходника.
- Вычисляемые условия (`1 == 1`, `!false`, переменные) не вычисляются анализатором.

## Объяснимые отказы

Выбранная ветка с `return`, `throw`, `break`, `continue` или безусловным циклом пока
не преобразуется. Удаление if может сделать следующий Java-код недостижимым для
компилятора. Проверка консервативна: учитывает переходы и во вложенном коде ветки.
Преобразование внутри окружающего try/catch/finally отклоняется: удаление мёртвой
ветки может изменить проверку достижимости catch для checked exceptions.
Вместо предположения пользователь получает причину отказа; проект остаётся прежним.

## Ревизии и проверка поведения

Предпросмотр привязан к владельцу проекта, ревизии, методу и блоку. Подтверждение
пересчитывает результат и сверяет SHA-256 с предпросмотром, затем атомарно обновляет
Java, граф и ревизию. Устаревший предпросмотр получает HTTP 409. Черновик, конфликт
вкладок и исходная вкладка отключают преобразование. Запоздалый ответ предпросмотра
не открывается для другого метода или проекта.

Проверка компиляции и выполнения идёт в настоящем изолированном Docker-исполнителе.
Она относится только к новой ревизии и выбранным входам. Ошибка компиляции, отсутствие
исполнителя, таймаут или различие результатов не подтверждают сохранение поведения.
Если проверку не удалось поставить в очередь, преобразованный код остаётся сохранён;
интерфейс показывает ошибку, пользователь может запустить проверку повторно.

## API

- `POST /api/projects/{id}/transformations/constant-branch/preview`:
  `{revision, methodId, nodeId}`. Возвращает фрагменты before/after, диапазон,
  идентификаторы выбора, sourceRevision и previewHash. Проект не меняется.
- `POST /api/projects/{id}/transformations/constant-branch/apply`:
  `{revision, methodId, nodeId, previewHash}`. Возвращает обновлённый проект.
- После apply клиент создаёт обычное задание `/checks` с новой ревизией и сценариями.
  UI делает это автоматически. API apply сам не выбирает тестовые входы за пользователя.
