# Финальный сценарий Java Blueprints

В [examples/BlueprintDemo.java](../examples/BlueprintDemo.java) 894 строки Java,
один public-класс с main, расчёт заказа, склад/корзина и каталог примеров управления,
коллекций и исключений. Вспомогательные примеры адаптированы из проверенного корпуса
проекта в классы одного файла. Граф исследуется по методам; это не диаграмма классов.

[scenarios.json](../examples/scenarios.json) содержит пять входов и известные
stdout исходной версии, а также ожидаемый вывод после намеренного изменения.
Поле `changedStdout` относится только к описанному ниже `+1`, не к произвольной правке.
Сравнение на этих входах не доказывает эквивалентность на всех входах.

## Воспроизведение в интерфейсе

1. Запустите приложение и настоящий worker по README либо откройте проверенное
   развёртывание из [журнала приёмки](../deploy/VALIDATION.md).
2. Загрузите `examples/BlueprintDemo.java`. Автоматически выбран `calculateTotal`.
   Другие методы, конструкторы, классы и объявления сохраняются в исходнике.
3. Нажмите «Анализировать». Найдите константное условие и перейдите от находки к
   исходнику и блоку графа. В отчёте также есть длинный main и вложенные циклы;
   у `sum(int)` оценка `O(n)` с допущениями, у неизвестных вызовов — «не определена».
4. Выберите `int subtotal = amount * quantity;` и замените на
   `int subtotal = amount * quantity + 0;`. Java и граф сохранятся новой ревизией.
5. Откройте «Проверить поведение». Пустой stdin выполняет заказ по умолчанию:
   `Итого: 1125`. Либо скопируйте до пяти сценариев из JSON: заказ со скидкой,
   без скидки, коллекции, обработанное исключение, склад/корзина.
6. Выберите условие `true`, откройте «Предпросмотр упрощения». До подтверждения
   исходник не меняется; после «Применить и проверить» сравнение запускается
   автоматически на текущих входах. Ожидается совпадение.
7. Для выделения метода выберите `calculateTotal`, первую операцию (объявление
   subtotal), диапазон из одной операции и имя `subtotalForOrder`. Просмотрите
   параметры `int amount`, `int quantity` и результат `int`, затем подтвердите.
   Новый метод появляется в списке; результаты остаются прежними.
8. Экспортируйте Java. Это рабочая версия с правками, исходная остаётся эталоном.
9. В новом `subtotalForOrder` замените операцию на
   `int subtotal = amount * quantity + 1;`. Старый результат становится историческим.
   Повторите проверку: заказ 250 × 5 даст 1126 вместо 1125, заказ 100 × 2 — 201
   вместо 200, корзина — 1261 вместо 1260. Коллекции и обработанное исключение
   остаются без изменений. Совокупный вердикт — «Есть различия».
10. Для отрицательного примера замените операцию на `int subtotal = missingValue;`.
    Синтаксический разбор допускает выражение, настоящий javac сообщает ошибку.
    Интерфейс показывает «Ошибка компиляции», результат проверки — незавершённый,
    совпадение не объявляется. Исправьте код или загрузите пример заново.

Ручные пункты 4–9 можно выполнять и без выделения метода: для `+1` достаточно
изменить первоначальное объявление subtotal в `calculateTotal`.

## Другие команды монолита

Первая строка stdin выбирает команду, остальные строки — её ввод.
`order` читает цену и количество (по умолчанию 250 и 5); `console` читает имя и число.
`stock`, `sum`, `rectangle`, `collections`, `primitives`, `declarations`, `caught`,
`uncaught`, `multi-catch`, `nested-finally`, `nested-cleanup`, `finally-override`
демонстрируют соответствующие части Java. `uncaught` намеренно завершает программу
пользовательским RuntimeException после finally.

Команды циклов: `while`, `for`, `do`, `foreach-array`, `foreach-list`, `nested`,
`return`, `infinite-for`, `unbraced`, `switch-colon`, `switch-arrow`, `switch-empty-labels`.
`infinite-for` имеет явный break и завершается. Неизвестная команда даёт исключение.

## Автоматическая проверка

```bash
# API: пять входов после каждого действия, обе трансформации, различие и ошибка javac
BLUEPRINTS_DOCKER_BIN=docker .venv/bin/pytest tests/test_final_demo.py -q
# Браузер: большой исходник, диагностика, граф, экспорт, упрощение, различие, javac
BLUEPRINTS_DOCKER_BIN=docker npm run test:e2e -- tests/browser/final-demo.spec.ts
# Тот же браузерный путь через настоящий HTTP-прокси без локального worker
BLUEPRINTS_DEMO_URL=http://SERVER npx playwright test --config deploy/playwright.config.ts
```

Последняя команда предназначена для свободного демо: проверки создают временные
проекты и задания, включая таймауты. Полный корпус, трансформации, независимость
посетителей, очередь и ограничения проверяются отдельными тестами; ссылки собраны
в [итоговой матрице](coverage.md).
