# Файлы проекта и консоль Java

В проводнике можно вручную разделить загруженный монолит на несколько `.java`.
Граф по-прежнему показывает один выбранный метод выбранного файла.
Автоматическое определение бизнес-областей и разделение по классам не выполняется.

## Ручное разделение

1. Загрузите исходный монолит. Он станет неизменяемым эталоном проекта.
2. В проводнике нажмите «Создать Java-файл». Укажите `Price.java` или
   `demo/Price.java`: папки отображаются деревом, пакет для нового шаблона берётся
   из пути. Либо добавьте готовый файл кнопкой загрузки внутри проводника.
3. В редакторе Java перенесите класс или часть логики в новый файл. В исходном
   рабочем файле удалите перенесённое объявление и добавьте нужные вызовы/import.
   Сохраняйте каждый изменённый файл кнопкой «Обновить граф».
4. Переключайтесь между файлами в проводнике. Черновики сохраняются отдельно
   в текущей вкладке браузера. Выбранный файл восстанавливается после перезагрузки.
5. Откройте «Консоль», проверьте класс с main рабочей и исходной версий и задайте
   stdin до запуска. Все рабочие Java-файлы компилируются **вместе**; исходный
   набор файлов компилируется отдельно. Точки входа двух версий могут различаться.
6. Запустите проверку. Сравниваются stdout, stderr, код завершения и сведения
   о необработанном исключении. Совпадение относится только к выбранным входам.
7. «Экспорт Java» скачивает выбранный рабочий файл, включая его текущий черновик.
   «Скачать проект ZIP» экспортирует весь сохранённый рабочий набор. Сначала
   сохраните черновики всех файлов, чтобы ZIP содержал все правки.

Переименование меняет путь файла; имя класса, пакет и ссылки в Java нужно менять
самостоятельно. Имя public-класса должно соответствовать имени файла — это проверит javac.
Удаление требует подтверждения. Оно удаляет файл из рабочего набора и его локальный
черновик; оригинал загруженного проекта остаётся эталоном. Последний файл удалить нельзя.
Верхний «Импорт Java» загружает **новый проект**, кнопка загрузки внутри проводника
добавляет файл в **текущий проект**.

## Консоль

Панель открывается кнопкой «Консоль» или «Проверить». Поддержаны многострочный
stdin, включая кириллицу, и отдельные stdout/stderr для обеих версий. До пяти
сценариев запускаются по очереди. Состояния очереди, ошибка javac, таймаут и
результат сравнения показываются явно. Это консоль запуска Java с заранее
заданным вводом; команды оболочки и ввод во время уже начавшегося исполнения
не поддерживаются. В стандартном сценарии со Scanner весь ввод задаётся строками
до нажатия «Запустить проверку».

Пока существуют несохранённые черновики, запуск отключён. Изменения любого файла
меняют общую ревизию проекта и делают прежнюю проверку исторической. Очередь
хранит копию всех исходных и рабочих файлов на момент постановки задания;
последующие правки не меняют уже созданную проверку.

## Границы и совместимость

- До 32 рабочих Java-файлов; до 256000 байт UTF-8 в одном файле и до 1 МиБ
  суммарного рабочего исходника. Ресурсы компиляции и исполнения ограничены.
- Пути относительные, например `demo/Price.java`; переходы `..`, абсолютные пути,
  обратные слеши и совпадения имён отклоняются. Новые имена состоят из идентификаторов.
- Внешние JAR, Maven/Gradle и произвольные ресурсы проекта не загружаются.
- Проекты и задания принадлежат сессии; ID проекта или файла не заменяет cookie.
- Общая ревизия защищает от потери изменений между вкладками. При конфликте
  черновик сохраняется, пользователь явно выбирает серверный или свой текст.
- Старые однофайловые проекты преобразуются при чтении. SQLite-таблица не меняется;
  перед обновлением публичного сервера сохраняется резервная копия всего тома.
  Новая структура payload требует использовать резервную копию данных при откате
  на версию приложения, которая не умеет читать многофайловые проекты.

## Сверка с обязательным слайдом Axenix

| Раздел | Проверка |
| --- | --- |
| Язык и java.lang | Корпусы `java_coverage`, `control_flow`; граф, правка, javac и выполнение |
| Консольный ввод-вывод | Scanner, Formatter, printf, String.format, StandardCharsets.UTF_8, stdout/stderr; браузерный ввод кириллицы |
| java.util | Все явно перечисленные на слайде типы представлены в `collections/Coverage.java` |
| Исключения | Checked/custom, unchecked, multi-catch/finally и отрицательная компиляция без catch/throws; java.util NoSuchElementException/InputMismatchException |

Это подтверждённые примеры, а не гарантия всех методов библиотек или сочетаний
конструкций Java. Матрицы [Java](java-coverage.md) и [управления](java-control-flow.md)
описывают границы структурного графа отдельно от возможностей настоящей JVM.
